# Technical Context for test-proxy-recorder

Website: [https://test-proxy-recorder.dev](https://test-proxy-recorder.dev)
Last Updated: 2026-07-31

## Overview

test-proxy-recorder is an npm package, not a hosted service. It runs entirely on the developer's machine and in CI. During a Playwright test run it sits between the application and the real backend: in `record` mode it proxies to the backend and persists every exchange to disk as `.mock.json` (server-side traffic) or HAR (browser traffic); in `replay` mode it serves those saved responses with no network access at all.

Requests are keyed per Playwright test through the `x-test-rcrd-id` session header, so a parallel suite stays isolated.

Requires Node.js >= 20 and `@playwright/test` >= 1.0.0 as a peer dependency. MIT licensed.

This website is the documentation for that package. It is a static Astro site — the marketing homepage at `/` and a Starlight documentation site under `/docs/`.

## API Information

status: not-available

There is no hosted HTTP API and no account system. The website is static and the package is installed from npm and run locally.

The package does expose two local interfaces during a test run:

- **Control endpoint** — `POST /__control` on the proxy's own port (default 8100). Flips the proxy between `record`, `replay`, and `transparent` at runtime, and is what Playwright's `webServer` health check points at. Bound to localhost, test-time only.
- **Programmatic API** — the TypeScript exports listed below, used from a Playwright fixture.

## CLI

```bash
test-proxy-recorder <target> --port 8100 --dir ./e2e/recordings   # run the proxy
test-proxy-recorder init <target> [--port] [--dir] [--config]      # scaffold into a project
test-proxy-recorder reset                                          # reset proxy mode
```

Flags: `--port`, `--dir`, `--config`, `--no-redact`, `--redact-headers`, `--redact-body`. CLI flags override the config file.

## Authentication

None, at any layer. The website is public and static; the proxy binds to localhost for the duration of a test run.

For applications that require a real login before recording, use `transparent` mode for the login step and switch to `record` afterwards.

## Security

Secret redaction is enabled by default and strips the `Authorization`, `Cookie`, and `Set-Cookie` headers before anything is written to disk. Extend it with `--redact-headers` and `--redact-body`. Recordings are committed to the user's repository, so redaction is the difference between a fixture and a leaked token.

Report security issues through [GitHub issues](https://github.com/asmyshlyaev177/test-proxy-recorder/issues).

## SDKs

The package is TypeScript-first and ships its own type definitions. There are no separate SDKs.
